Each atomic task allows at most three code repairs after the initial implementation.

Human gate actions

Gate 1

Approve refined requirement and unresolved-question resolution. The Requirement Validation and Requirement Confirmation sub-issues must be moved to their human-only Done states.

Gate 2

Approve product specification, user flow, acceptance criteria, and prototype. Prototype Confirmation becomes Prototype Analyze Done.

Gate 3

Approve technical design, atomic tasks, and manual E2E test cases. Both Task Breakdown and Test Cases become Dev Analyze Done.

Gate 4

Approve PR, merge, and release readiness. Development Execution becomes Development Done.

After every human-only Done transition, the primary agent must read it back and receive an explicit next-step instruction before moving the main issue. Agents never automatically set a Start … state.
